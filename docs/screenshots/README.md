# Screenshots

Two sets live here. They answer different questions and are produced differently.

| Set | Where | Source | Used by |
|---|---|---|---|
| Demo stack | `docs/screenshots/*.png` | **Generated** from the demo compose stack and seeded demo data | The project documentation (see the [README](../../README.md)) |
| Real run | `docs/screenshots/real-run/` | **Captured** from a live public-IP deployment (5 days) | [RESULTS.md](../RESULTS.md) |

## Demo stack (generated)

Regenerate these rather than replacing them by hand, so they cannot drift from what the software
renders.

| File | What it shows |
|---|---|
| `console.png` | The built-in operations console (`:8090`): live attack feed, sensor health, volume by severity |
| `overview.png` | Grafana: severity over time, top attackers, per-engine breakdown |
| `threat-map.png` | Grafana: geo-located attacker origins |
| `mitre.png` | Grafana: MITRE ATT&CK tactic coverage |

```bash
./scripts/capture_screenshots.sh
```

That brings the demo stack up with a headless-Chromium renderer sidecar, seeds demo data if the last
24 hours are empty, and writes all four PNGs here at 1920px wide. Requires Docker; everything else
runs in containers.

Tear the renderer back down afterwards; it is a ~400 MB image a normal demo run has no use for:

```bash
docker compose -f docker/docker-compose.yml \
               -f docker/docker-compose.screenshots.yml down
```

## Real run (captured)

Captured from the live deployment that [RESULTS.md](../RESULTS.md) reports on. They are
not regenerated by the script above.

| File | What it shows |
|---|---|
| `real-run/overview.png` | Grafana overview: alerts, unique sources, severity over time, per-engine split |
| `real-run/threat-map.png` | Grafana: attacker origins and top countries |
| `real-run/mitre-coverage.png` | Grafana: ATT&CK tactics and event types, rendered on the final database |
| `real-run/operations-console.png` | The operations console against the live database |
| `real-run/attack-navigator.png` | ATT&CK Navigator view of the layer written by `generate_report format=attack_navigator` (then the `attack_navigator_layer` tool), final database |
| `real-run/attack-navigator-layer.json` | The layer file, regenerated on the final database (17,726,494 alerts) with the current mapping |
| `real-run/final-overview.png` | Grafana overview on the **final** database, whole run (11 to 16 Oct, UTC): 17.7M alerts, severity over time, per-engine split, top attackers |
| `real-run/final-threat-map.png` | Grafana threat map on the final database: origins, top countries, unique attackers over time |
| `real-run/final-mitre-coverage.png` | Grafana ATT&CK dashboard on the final database: tactic bars, event types, tactic timeline |
| `real-run/final-alerts.png` | Grafana alert browser (filters and newest alerts) on the final database |

The first group (`overview`, `threat-map`, `mitre-coverage`) are crops taken while the run was still
going, so their counts are lower than the final figures in RESULTS.md; each caption there says when
the snapshot was taken. The `final-*` captures are whole dashboards from `grafana_start` on the
finished database, rendered by headless Chromium after every panel had loaded (the heavy panels take
one to two minutes over 17.7M rows).

## Claude Code sessions (captured)

Real `claude -p` sessions with the server connected, asking plain questions of the final database.
The reply text is Claude's own; the layout is re-typeset to look like a terminal, and the tool-call
lines show which tools it chose. One closing remark about a private note-taking setup was removed
from two replies. Claude's prose includes its own inferences (for example "the same operator"), which
are not facts the tools return.

| File | Question |
|---|---|
| `claude-code/shift-handover.png` | "Give me a shift handover for the whole run." |
| `claude-code/is-this-a-botnet.png` | "Is 164.30.x.x part of a botnet, and what did it do?" (uses `fingerprint_clusters(ip=...)`) |
| `claude-code/pcap-suricata-replay.png` | "Replay the attacker packet capture … through Suricata and tell me what it found." (`pcap_detect`) |

**Source addresses.** The older `real-run/` crops show counts and countries only. The `final-*` and
`claude-code/` images contain attacker addresses **masked to their first two octets** (`103.132.x.x`),
including inside the Grafana tables (masked in the page before capture). Check a new capture for
source addresses and credentials before committing it.

## Notes for whoever touches this next

- The seed check counts events **inside the render window**, not rows in the table. A database
  seeded yesterday is full of data and still renders empty panels, so a stale window triggers a
  reseed.
- Dark throughout: the Grafana stack sets `GF_USERS_DEFAULT_THEME=dark`, and the console is dark by
  design.
- If a Grafana panel shows "No data" while the same SQL works through the API, check that every
  target carries `rawQueryText`. The SQLite plugin's frontend interpolates from that field, and
  without it the browser sends an empty query.
