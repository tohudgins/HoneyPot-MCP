# Screenshots

The committed screenshots are all captured from the real run: Grafana and the console on the finished
17.7M-alert database, and real Claude Code sessions. Nothing here is generated.

`scripts/capture_screenshots.sh` can still render the console and three Grafana dashboards from the demo
compose stack and seeded demo data (`console.png`, `overview.png`, `threat-map.png`, `mitre.png`). Those
outputs are not committed, because the real-run captures below replace them.

```bash
./scripts/capture_screenshots.sh
```

It needs Docker and brings up a ~400 MB headless-Chromium renderer sidecar. Tear it down afterwards:

```bash
docker compose -f docker/docker-compose.yml \
               -f docker/docker-compose.screenshots.yml down
```

That brings the demo stack up with a headless-Chromium renderer sidecar, seeds demo data if the last
24 hours are empty, and writes all four PNGs here at 1920px wide. Requires Docker; everything else
runs in containers.

Tear the renderer back down afterwards; it is a ~400 MB image a normal demo run has no use for:

```bash
docker compose -f docker/docker-compose.yml \
               -f docker/docker-compose.screenshots.yml down
```

## Claude Code sessions (captured)

Real, interactive Claude Code sessions with the server connected, asking plain questions of the final
database. Each image is the actual Claude Code screen: the client's own layout, tool-call lines
("Called honeypot", collapsed as Claude Code shows them), reply and prompt box. Nothing was
re-typeset. They were captured by running `claude` in a pseudo-terminal and drawing its raw terminal
output with xterm.js in headless Chromium, with its tools limited to the honeypot server. Two
things were done to the capture, and nothing else:

- attacker addresses were masked in place, keeping their length (`108.186.xx.xx`), so the layout is
  untouched;
- the empty rows between the reply and the prompt box were collapsed, as if the terminal window were
  exactly as tall as the conversation.

The grey text in the prompt box at the bottom of some images is Claude Code's own follow-up
suggestion, not something typed. The model's prose includes its own inferences (for example "looks
like an authorised tester" or "the same operator"), which are not facts the tools return. The
banner shows the Claude Code version and model used.

credentials before committing it.

## Notes for whoever touches this next

- The seed check counts events **inside the render window**, not rows in the table. A database
  seeded yesterday is full of data and still renders empty panels, so a stale window triggers a
  reseed.
- Dark throughout: the Grafana stack sets `GF_USERS_DEFAULT_THEME=dark`, and the console is dark by
  design.
- If a Grafana panel shows "No data" while the same SQL works through the API, check that every
  target carries `rawQueryText`. The SQLite plugin's frontend interpolates from that field, and
  without it the browser sends an empty query.
