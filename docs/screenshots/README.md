# Screenshots

Two sets live here. They answer different questions and are produced differently.

| Set | Where | Source | Used by |
|---|---|---|---|
| Demo stack | `docs/screenshots/*.png` | **Generated** from the demo compose stack and seeded demo data | The project documentation (see the [README](../../README.md)) |
| Real run | `docs/screenshots/real-run/` | **Captured** from a live public-IP deployment (5 days) | [RESULTS.md](../RESULTS.md) |

## Demo stack (generated)

Regenerate these rather than replacing them by hand, so they cannot drift from what the software
renders.

| File | What it shows |
|---|---|
| `console.png` | The built-in operations console (`:8090`): live attack feed, sensor health, volume by severity |
| `overview.png` | Grafana: severity over time, top attackers, per-engine breakdown |
| `threat-map.png` | Grafana: geo-located attacker origins |
| `mitre.png` | Grafana: MITRE ATT&CK tactic coverage |

```bash
./scripts/capture_screenshots.sh
```

That brings the demo stack up with a headless-Chromium renderer sidecar, seeds demo data if the last
24 hours are empty, and writes all four PNGs here at 1920px wide. Requires Docker; everything else
runs in containers.

Tear the renderer back down afterwards; it is a ~400 MB image a normal demo run has no use for:

```bash
docker compose -f docker/docker-compose.yml \
               -f docker/docker-compose.screenshots.yml down
```

## Real run (captured)

Captured from the live deployment that [RESULTS.md](../RESULTS.md) reports on. They are crops of
the dashboards and console, not regenerated by the script above, and they show counts and
countries, never source addresses.

| File | What it shows |
|---|---|
| `real-run/overview.png` | Grafana overview: alerts, unique sources, severity over time, per-engine split |
| `real-run/threat-map.png` | Grafana: attacker origins and top countries |
| `real-run/mitre-coverage.png` | Grafana: ATT&CK tactics and event types (captured before the SIP remapping) |
| `real-run/operations-console.png` | The operations console against the live database |
| `real-run/attack-navigator.png` | ATT&CK Navigator layer from the `attack_navigator_layer` tool (captured before the SIP remapping) |
| `real-run/attack-navigator-layer.json` | The layer file, regenerated on the final database (17,726,494 alerts) with the current mapping |

Snapshots were taken while the run was still going, so their counts are lower than the final
figures in RESULTS.md; each caption there says when the snapshot was taken. Check a new capture for
source addresses and credentials before committing it.

## Notes for whoever touches this next

- The seed check counts events **inside the render window**, not rows in the table. A database
  seeded yesterday is full of data and still renders empty panels, so a stale window triggers a
  reseed.
- Dark throughout: the Grafana stack sets `GF_USERS_DEFAULT_THEME=dark`, and the console is dark by
  design.
- If a Grafana panel shows "No data" while the same SQL works through the API, check that every
  target carries `rawQueryText`. The SQLite plugin's frontend interpolates from that field, and
  without it the browser sends an empty query.
