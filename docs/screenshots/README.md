# Screenshots

Two sets live here. They answer different questions and are produced differently.

| Set | Where | Source | Used by |
|---|---|---|---|
| Demo stack | `docs/screenshots/*.png` | **Generated** from the demo compose stack and seeded demo data | The project documentation (see the [README](../../README.md)) |
| Real run | `docs/screenshots/real-run/` | **Captured** from a live public-IP deployment (5 days) | [RESULTS.md](../RESULTS.md) |

## Demo stack (generated)

Regenerate these rather than replacing them by hand, so they cannot drift from what the software
renders.

| File | What it shows |
|---|---|
| `console.png` | The built-in operations console (`:8090`): live attack feed, sensor health, volume by severity |
| `overview.png` | Grafana: severity over time, top attackers, per-engine breakdown |
| `threat-map.png` | Grafana: geo-located attacker origins |
| `mitre.png` | Grafana: MITRE ATT&CK tactic coverage |

```bash
./scripts/capture_screenshots.sh
```

That brings the demo stack up with a headless-Chromium renderer sidecar, seeds demo data if the last
24 hours are empty, and writes all four PNGs here at 1920px wide. Requires Docker; everything else
runs in containers.

Tear the renderer back down afterwards; it is a ~400 MB image a normal demo run has no use for:

```bash
docker compose -f docker/docker-compose.yml \
               -f docker/docker-compose.screenshots.yml down
```

## Claude Code sessions (captured)

Real, interactive Claude Code sessions with the server connected, asking plain questions of the final
database. Each image is the actual Claude Code screen: the client's own layout, tool-call lines
("Called honeypot", collapsed as Claude Code shows them), reply and prompt box. Nothing was
re-typeset. They were captured by running `claude` in a pseudo-terminal and drawing its raw terminal
output with xterm.js in headless Chromium, with its tools limited to the honeypot server. Two
things were done to the capture, and nothing else:

- attacker addresses were masked in place, keeping their length (`108.186.xx.xx`), so the layout is
  untouched;
- the empty rows between the reply and the prompt box were collapsed, as if the terminal window were
  exactly as tall as the conversation.

The grey text in the prompt box at the bottom of some images is Claude Code's own follow-up
suggestion, not something typed. The model's prose includes its own inferences (for example "looks
like an authorised tester" or "the same operator"), which are not facts the tools return. Two sessions
ran on slightly different Claude Code versions; the banner shows which.

| File | Question (and the tool that answers it; Claude Code collapses its calls to "Called honeypot") |
|---|---|
| `claude-code/shift-handover.png` | "Give me a shift handover for the whole run." (`soc_brief` and follow-ups) |
| `claude-code/bait-credential.png` | "Who used the public bait credential, and what did they do first?" (`bait_trips`) |
| `claude-code/is-this-a-botnet.png` | "Is 164.30.x.x part of a botnet, and what did it do?" (`fingerprint_clusters(ip=...)`, journey, patterns) |
| `claude-code/pcap-suricata-replay.png` | "Replay the attacker packet capture … through Suricata and tell me what it found." (`pcap_detect`) |
| `claude-code/malware-samples.png` | "What malware did attackers try to drop, and what is in the captured files?" (`extract_iocs`, `sample_scan`) |
| `claude-code/decoy-plan.png` | "Design decoys for a small Windows domain with a Postgres warehouse behind it. Don't deploy anything." (`deception_plan`) |
| `claude-code/sql-query.png` | "Use SQL to show how many alerts per day each of the three busiest source addresses sent." (`sql_query` over `alert_rollups`) |
| `claude-code/attack-navigator-layer.png` | "Give me an ATT&CK Navigator layer file for the whole run." (`generate_report`, `format=attack_navigator`) |

**Source addresses.** The older `real-run/` crops show counts and countries only. The `final-*`
captures contain attacker addresses **masked to their first two octets** (`103.132.x.x`), including
inside the Grafana tables (masked in the page before capture); the `claude-code/` images mask the
last two octets as above. Check a new capture for source addresses and credentials before committing it.

## Notes for whoever touches this next

- The seed check counts events **inside the render window**, not rows in the table. A database
  seeded yesterday is full of data and still renders empty panels, so a stale window triggers a
  reseed.
- Dark throughout: the Grafana stack sets `GF_USERS_DEFAULT_THEME=dark`, and the console is dark by
  design.
- If a Grafana panel shows "No data" while the same SQL works through the API, check that every
  target carries `rawQueryText`. The SQLite plugin's frontend interpolates from that field, and
  without it the browser sends an empty query.
